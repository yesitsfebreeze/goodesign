# First run, and the long run

**Read when:** designing an empty state, onboarding, or anything a returning
power user touches daily.

- **The empty state is the onboarding.** It says what goes here, why it matters,
  and gives one action to start. Never a blank rectangle, never a shrug, never
  "No items found." as the whole design. It needs warmth, a primary action, and
  context.
- **Do not tour; seed.** A product that must be explained by an overlay tour has
  a design problem the tour is hiding. Prefer sample data, a first item created
  for them, or a single inline hint at the moment of need.
- **Design the twelfth session, not the first.** Shortcuts, density, bulk
  actions and keyboard paths are what a returning user actually feels.
- **Accessibility is a UX requirement, not a compliance step.** Keyboard-only
  and screen-reader paths complete the same jobs, in the same number of steps.

## The three time horizons

Design for all three at once:

```
first 5 seconds    visceral   — does this look like it was made on purpose?
first 5 minutes    behavioural — can they do the job without reading anything?
five years         reflective — do they trust it with the thing that matters?
```
